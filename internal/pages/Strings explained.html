Strings explained

On string storage and operations.
Last modified 23/04/2026

Context: yesterday I saw a post on X saying that strings are “slow”, and provided some reasons for why that would be. Leaving aside the fact that those stated “facts” are wrong, I think knowing how things work is much better than memorizing some trivia that you will most likely forget in the future.

Variables and storage

Every piece of data takes up some space in memory.

Many programming languages use types Types are used for other things too, but that is another story. to define the amount of memory that a piece of data will take up. For example, in C and C++, one might say that they want a variable of type int and, on most computers, compilers will generate code to reserve 4 bytes of space for that variable. You can easily get this information through the sizeof operator.

C 
int a = 0x42;

If you want to be sure that the size is what you expect and the compiler supports it, you can include the <stdint.h> header and use int32_t. This way you explicitly say that you want the variable to be 32 bits (4 bytes) in size.

C 
int32_t a = 0x42;

Of course this puts a limit to how many possible numbers can be represented by that variable. 32 bits of storage means 232 (or 4’294’967’295) combinations of bits: the range of values that we can represent in a 32-bit variable is [0, 4’294’967’295], or [-2’147’483’648, 2’147’483’647] if we choose to reserve half of it for the negatives.

For a beginner this may sound like a problem: what if I need a bigger range? Then, with practice and experience, you learn to worry about problems you have instead of the ones you might have. Depending on the domain of the problems you’re solving, you could even realize that you almost never need anything outside that range and, for the few cases where you do, there are solutions you can implement.

The compiler and the stack

What is the advantage of knowing the size of variables ahead of time? It’s so that the compiler can generate extremely efficient code.

For starters, allocation (reserving the memory necessary to hold the variables) and deallocation (releasing the memory so that it can be reused later) can be reduced down to one instruction each. Imagine a big, invisible array of bytes living inside your program, called the stack; there’s also an index into this array, called the stack pointer. The stack is where all your local variables are stored. The stack pointer keeps track of which elements of the stack are considered “free”, so that new variables won’t overwrite the ones that already exist.

For each function, the compiler computes the total sum of the sizes of all the local variables it has. Then, when generating the function’s code, it starts with an instruction that increments the stack pointer by that amount. At the end of the function, another instruction moves the stack pointer back to where it was.

This is why some C compilers (and all C++ compilers!) don’t allow you to use a variable as the length of an array: you would make it impossible for it to predict the size of the allocation.

The complexity of strings

The reason that it makes sense to store numbers in fixed-size variables is because it is possible to define the concept of a range. Every value inside that range will get a dedicated combination of the N available bits for that variable size. As the program does operations on a numeric variable, only the value stored in the variable changes, not its size.

Strings are complicated. You can’t define a range of strings in a way that makes sense for all applications. They necessarily have to be represented as an ordered collection of smaller elements. As the program operates on these collections, they will have to vary in size.
